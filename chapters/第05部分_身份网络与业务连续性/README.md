# 第5部分　身份、网络与业务连续性

## 部分定位

本部分补齐的是三个**一级安全域**，它们的共同特点是：不新、不酷、没有前沿叙事，但企业安全预算的大头在这里，安全事故的入口也在这里。

- **第14章 企业身份与访问管理**——Verizon DBIR 十年来的第一大入口，也是多数企业安全预算的第一大项。
- **第15章 网络、基础设施与终端安全**——CIS Controls v8.1 的 IG1 基础卫生层，缺失的四项（账户管理、邮件与浏览器防护、恶意软件防护、数据恢复）有三项落在这里。
- **第16章 业务连续性与灾难恢复**——NIST CSF 2.0 六大功能里的 RECOVER。事件响应不等于恢复，能遏制不等于能恢复。

适用读者：安全负责人（CSO/CISO）、身份治理负责人、基础设施与终端安全工程师、业务连续性负责人、SOC 与 IR 团队。

---

## 为什么这三章单独成部

它们的共同点不是技术相近，而是**在企业里的处境相近**：不新、不酷、没有前沿叙事，但预算的大头在这里，事故的入口也在这里。

- **第14章 企业身份与访问管理**——Verizon DBIR 十年来的第一大入口，也是多数企业安全预算的第一大项。
- **第15章 网络、基础设施与终端安全**——CIS Controls v8.1 的 IG1 基础卫生层，缺失项大量落在这里。
- **第16章 业务连续性与灾难恢复**——NIST CSF 2.0 六大功能里的 RECOVER。事件响应不等于恢复，能遏制不等于能恢复。

**关于阅读顺序的一点说明**：如果你的环境以本地基础设施为主，建议把本部提到第2部分之前读——第14章的企业身份体系是 5.2 云 IAM 的本体，第15章的本地网络架构是 5.3 云网络的对照面，先读本体再读投影更顺。如果你的环境已经以云为主，按章号顺序读即可。

## 与其他部分的关系

- **承接第1部分**：身份治理的组织归属、韧性的风险口径来自第2章 GRC。
- **前置于第2部分**：企业身份体系是云 IAM（5.2）的本体，本地网络架构是云网络（5.3）的对照面。按章号顺序读会先看到投影、后看到本体。
- **向第3部分供给**：身份是数据访问控制（8.5）的授权来源，终端是 DLP（10.3）的执行点。
- **与第4部分互补**：第11章的检测消费本部分产生的身份与终端信号；第16章接手第11章事件响应结束之后的恢复阶段——**事件响应不等于业务连续性**。
- **与第6部分呼应**：AI agent 作为非人类身份的治理见 14.8，AI 系统的连续性见 18.7.4 与第16章。
