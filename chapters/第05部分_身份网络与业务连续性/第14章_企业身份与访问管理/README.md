# 第14章　企业身份与访问管理

过去五年公开披露的重大入侵里，攻击者极少去打穿一台防火墙——他们登录进来。用的是真实账号、真实密码、真实的会话令牌，有时还通过了多因素认证。身份不是安全体系的一个模块，它是攻击者的默认入口，也是防守方最难说清"现状是什么"的一块。

这一章要处理的核心矛盾是：**身份系统的所有权在 IT，风险的承担者是安全**。发放账号、开通权限、重置密码这些天然属于 IT 运维的效率范畴，KPI 是"多快能让新员工干活"；而离职当天权限是否真的收回、一次转岗积累了多少不该有的权限、域管理员组里那三个"临时加进去的"账号是谁——这些是安全的风险敞口。两套目标函数长期错位，制造出本章反复出现的一种现象：**每一项控制单独看都在运行，合起来却拦不住任何人**。MFA 覆盖率报表是 100%，但备用短信通道谁都能走；PAM 纳管了 1200 个特权账号，而云控制台的 12 个管理员根本不在纳管范围；访问审阅完成率 98%，撤销率 1.7%。本章要给的是判断：**哪些控制值得做，哪些做了也白做，以及在真实企业里它们会以什么方式失败**。

## 术语约定

身份领域缩写密度高，且不同厂商对同一概念叫法不同。本章统一采用下表写法，首次出现时给全称，之后使用缩写。

| 缩写 | 全称 | 本章含义 |
|------|------|---------|
| IdP | Identity Provider | 身份提供商，认证的中心，向应用颁发断言或令牌 |
| IGA | Identity Governance and Administration | 身份治理与管理，覆盖供给、审阅、角色与合规报告 |
| JML | Joiner-Mover-Leaver | 入职-转岗-离职三类生命周期事件 |
| SCIM | System for Cross-domain Identity Management | 跨域身份供给协议，RFC 7643/7644 |
| PAM | Privileged Access Management | 特权访问管理，含保险箱、会话代理、JIT |
| ZSP | Zero Standing Privilege | 零常驻权限，特权默认不存在、按需临时产生 |
| NHI | Non-Human Identity | 非人类身份，含服务账号、工作负载、API 客户端、AI agent |
| CIAM | Customer IAM | 面向外部客户的身份管理，与企业内部 IAM 目标函数不同 |
| ITDR | Identity Threat Detection and Response | 身份威胁检测与响应 |
| ISPM | Identity Security Posture Management | 身份安全态势管理，关注配置与暴露面而非实时告警 |

需要特别区分两组容易混用的概念。**认证（Authentication）与授权（Authorization）**：前者回答"你是谁"，后者回答"你能做什么"，本章 14.3 与 14.4 分别对应，二者的失效模式完全不同——认证失效是被冒充，授权失效是被滥用。**IGA 与 PAM**：前者管普通身份的"多"（数万条身份、数十万条权限，靠流程与自动化），后者管特权身份的"重"（数百个账号，靠强控制与审计），把两者用同一套流程管理是常见的架构错误。

## 本章的证据分级约定

安全领域充斥着无法复核的数字。本章对每一处量化陈述标注来源强度：**公开披露**（监管通报、官方事件报告、厂商安全公告或标准文本，行内以 `[n]` 编号，可在各节文末参考文献表核对）、**厂商称，需自证**（厂商白皮书或行业报告，方法论通常不公开）、**示例口径，非行业基准**（为让方法可操作而构造的阈值，不代表行业平均水平）、**推演**（对尚未定型的技术或监管走向的判断，属于分析而非事实）。

本章以 2026 年 7 月为截稿时点。变化最快的两个方向是 Passkey 的企业级管理能力与 AI agent 作为受管身份的标准化，落地前应核对最新的产品能力与规范版本。
