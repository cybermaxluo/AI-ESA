## 部分定位

本部分承接 第1部分战略治理层的顶层设计，将安全架构转化为可执行的技术方案与工程实践。从零信任架构设计、云原生安全架构、应用安全生命周期到供应链安全治理，覆盖企业技术栈的核心安全控制点。

**本部分的边界（先读这一段，避免找错地方）**：标题里的"基础设施"指的是**云与软件交付这一侧的基础设施**——云平台、应用运行时、构建与依赖链。**网络、终端、数据中心机房这三块的工程落地不在本部分**，它们在 [第15章　网络基础设施与终端安全](../第05部分_身份网络与业务连续性/第15章_网络基础设施与终端安全/)。

两边的分工是**设计层与工程层**，不是主题切分：

| 你想找的 | 本部分给你 | 第15章给你 |
|---|---|---|
| 零信任 | 架构模型、信任边界、参考架构（4.4、4.7） | 信任域划分标准与 5×5 策略矩阵（15.1） |
| 微隔离 | 架构模式、技术实现方式、适用边界（4.4.3） | 选型决策树、成本曲线、观察→强制的五阶段与退出条件（15.2） |
| SSE / SASE | 概念界定、架构位置（4.4.4） | 采购边界、七条实测选型判据、连接器与单点依赖（15.9） |
| 边界防护 | 云上 WAF 与规则分层（5.3.4） | 南北向组件的串联顺序与职责边界（15.3） |

**规则**：本部分不给实施排期、产品选型与运行指标——那些与具体环境强绑定，写在设计层会很快过期，也容易与工程章的口径分叉（历史上确实分叉过，见《编写规范.md》九）。跨领域的实施排序见 15.12。

适用读者：安全架构师、云安全工程师、应用安全工程师、DevSecOps 工程师。

前置要求：建议先完成 第1部分第1章（企业架构基础）的阅读，理解安全架构在企业架构中的嵌入逻辑。

与其他部分的关系：

- 承接 第1部分战略框架，输出具体技术架构与控制设计
- 向 第3部分提供认证授权机制与数据访问控制基础
- 为 第4部分安全运营提供检测数据源与架构可观测性设计
- 在 第6部分中延伸为 AI 驱动的安全架构优化场景

---

> 范围说明：本部分的"基础设施安全"以**云与云原生**为重心。企业本地网络架构、网络分段、边界防护、终端管理、邮件安全与资产治理见 **[第15章](../第05部分_身份网络与业务连续性/第15章_网络基础设施与终端安全/)**；企业身份体系（本部分 5.2 云 IAM 的本体）见 **[第14章](../第05部分_身份网络与业务连续性/第14章_企业身份与访问管理/)**。
