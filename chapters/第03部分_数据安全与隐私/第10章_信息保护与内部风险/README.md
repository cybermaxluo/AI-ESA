# 第10章　信息保护与内部风险

## 章节概述

本章处理企业信息安全里最不容易用技术解决的一面：**已经获得授权的人，如何不把信息带走。**

外部攻击者需要先突破边界才能碰到数据，而员工每天都在合法地访问它。这决定了本章所有控制的共同特征——它们不能靠"拒绝访问"来防护，只能在正常业务行为与外泄行为之间做判别，而这条界线永远模糊。DLP 的误报治理、内部风险的调查纪律、离职窗口的特殊处置，本质上都是在处理这种模糊性。

## 第8章与第10章的划界

两章按**威胁模型**划界——不是按抽象层次（战略 vs 运营），也不是按数据形态（结构化 vs 非结构化）。前两种口径都不成立：按层次切，读者要落地一个 DLP 得翻两章；按形态切，分类分级和 DLP 骑在轴上、必须被劈成两半。

| | 第8章　数据安全 | 第10章　信息保护与内部风险 |
| --- | --- | --- |
| 防的对象 | **未授权者进来** | **已授权者带走** |
| 控制落点 | 系统与数据存储 | 人与终端 |
| 典型控制 | 分类引擎、加密与密钥、访问控制模型、DAM、审计日志、跨境合规 | 文档标签与用户合规、IRM/DRM、DLP、内部风险处置、离职闭环、商业秘密 |
| 失效长什么样 | 数据库被拖库、密钥泄露、越权查询 | 员工把源码打包带走、误发客户名单、离职前批量下载 |

**判定规则：一个控制归哪章，问它拦的是谁。** 分类引擎服务于所有控制、防的是数据被误置于错误保护等级，归第8章；用户打错标签的培训与审计是人的行为，归第10章。DLP 拦的是内部人员外发，整体在第10章；其内容检测能力复用 8.2 的分类引擎，接口见 8.6。UEBA 的基线算法是监控技术，归 8.7.2；内部风险语境下如何消费它的输出、如何与 HR 和法务协同，归 10.4。

这条轴和"结构化 vs 非结构化"在实践中高度重合，因为威胁模型跟着数据形态走——但威胁模型是因、形态是果。写出因，边界案例才判得掉。

## 与其他章节的关系

- **第8章 数据安全** — 本章的技术底座。分类引擎（8.2）、加密（8.4）、访问控制（8.5）、UEBA 算法（8.7.2）都在那里，本章直接消费，不重复实现。
- **第9章 隐私合规** — 员工监控与内部调查的**法律边界**在那里。UEBA 采集什么行为数据、能保留多久、跨法域员工能不能一视同仁，这些问题本章不给答案，见 9.x。
- **第7章 供应链安全** — 开源许可证合规的技术实施（SCA/SBOM/CVE 闭环）在 7.3，本章 10.6.4 只从知识产权视角补充。
- **第19章 安全领导力** — 离职流程、背景调查、安全文化的组织侧建设在那里。
