# 8.6　数据丢失防护：与分类引擎的接口

> 本节是一个接口说明，不是 DLP 的完整内容。**DLP 的架构、部署模式、内容检测技术、策略调优、运营流程与效果度量，统一见 [10.3 数据丢失防护（DLP）](../第10章_信息保护与内部风险/10.3_数据丢失防护.md)。**

## 8.6.1　为什么 DLP 不在第8章展开

第8章与第10章按**威胁模型**划界：第8章解决"未授权者拿不到"，控制落在系统与数据存储上；第10章解决"已授权者带不走"，控制落在人与终端上。

DLP 拦截的对象是已获授权的内部人员——员工把源码打包外发、把客户名单误发给外部收件人、离职前批量下载。它属于后者。

DLP 的架构与策略调优在工程上无法分开：调优的每一次改动都要回到检测引擎的能力边界上去判断，脱离架构谈调优只能得到一堆无法执行的原则。因此 DLP 整体归第10章，本节只做接口说明。

## 8.6.2　本章向 DLP 提供什么

DLP 的内容识别能力**不是 DLP 自己的能力**，而是复用本章 8.2 的分类引擎。两者的接口是：

| 本章提供 | DLP 侧如何消费 | 对应小节 |
| --- | --- | --- |
| 分级模型（Public / Internal / Confidential / Restricted） | 作为策略的触发条件与处置强度分档 | 8.2.1 |
| 正则、关键字、文档指纹、Luhn 等校验算法 | 作为内容检测规则的原子能力 | 8.2.2 |
| ML 分类器与置信度阈值 | 作为规则命中之外的补充判据 | 8.2.2 |
| 标签（元数据 / xattr / S3 Object Tags） | 作为端点与网关侧的快速判定依据，避免每次重新做内容检测 | 8.2.3 |
| 数据资产清单与所有者信息 | 告警定责与工单派发的依据 | 8.2.4 |

两条常被忽略的工程后果：

**DLP 的误报率上限由分类引擎的精确率决定。** 如果 8.2 的分类规则本身精确率只有 70%，DLP 无论怎么调策略都压不下去——这时该修的是分类规则，不是 DLP 策略。这个因果关系在实践中经常被搞反：团队盯着 DLP 控制台反复调阈值、加例外，却从没回头看过底层规则的命中质量，结果是例外清单越滚越长而误报率纹丝不动。10.3.3 讨论误报治理时会反复回到这个前提。

**标签是性能优化，不是安全边界。** 攻击者可以剥掉文件的 xattr 标签，压缩、改扩展名、复制到不保留扩展属性的文件系统都会让标签丢失，因此端点 DLP 不能只信标签、必须保留内容检测兜底。标签真正的价值在于让 95% 的正常文件走快路径，把昂贵的内容检测留给剩下的 5%——它解决的是性能问题，不是判别问题。把标签当成判别依据的部署，在对抗性场景下等同于没有 DLP。
